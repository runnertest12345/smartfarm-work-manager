## 요금과 날짜

- 66,000원당 1년입니다. 66,000원 미만 구독 입금은 거부합니다.
- 132,000원은 2년, 198,000원은 3년입니다. 임의 반올림을 막기 위해 자동 연장은 66,000원 정수 배수만 받습니다.
- 현재 관리대장의 만료일이 **파모스앱 사용 만료일 기준값**입니다. 파모스앱 API와 직접 연동된 것은 아니므로 날짜가 일치해야 합니다. 만료일이 없으면 먼저 입력해야 합니다.
- 만료 전 또는 만료일부터 달력 기준 **2개월 이내(경계일 포함)** 결제: 기존 만료일부터 구매한 연수만큼 연장합니다.
- 2개월 초과 후 결제: 결제일부터 구매한 연수만큼 지난 **해당 월 마지막 날**이 새 만료일입니다.
- 달력에 없는 날짜는 해당 월 말일로 보정합니다. 2개월은 60일이 아닙니다.

## 회차와 화면

농가·사업 참여별 실제 양수 입금 기록을 셉니다. 첫 입금=1차 갱신, 두 번째 입금=2차 갱신이며 이후 3차·4차 순으로 증가합니다. 2년 선납도 입금 한 번이면 회차는 한 번만 증가합니다. 기존 수기 갱신횟수 대신 실제 서버 입금 내역을 기준으로 초기화하고 이후 회차를 저장합니다.

새 입금 업무의 최초 기록과 기존 입금 업무의 기록 추가 모두 적용합니다. 저장 전 예상 만료일·연장 기간·이번 입금 회차를 보여주며, 저장한 원본 입금 이력에 이전/새 만료일·연장 연수·확정 입금 차수와 갱신 이벤트 링크를 함께 남깁니다. 갱신 상태는 자동 등록되고, 새 만료일이 현재 유효하면 사용중으로 바뀝니다.

수신함에서 입금 업무로 전환할 때도 사용자가 입력한 실제 결제일을 사용합니다. 원본 수신 기록의 금액은 0, 실제 입금 기록은 한 번만 저장합니다. 금액 0은 입금이 아닌 일반 업무 기록/계획으로 허용하며 구독을 연장하지 않습니다. 다른 업무 유형의 금액에는 자동 연장을 적용하지 않습니다.

## 안전 장치

입금·업무 변경·갱신 이벤트·만료일·회차를 한 거래로 저장합니다. 같은 요청 ID의 재전송은 기존 성공 결과를 반환하고 다시 연장하지 않습니다. 동일 요청 ID로 금액 등 내용을 바꾸면 거부합니다. 실제로 별도 입금한 경우는 새 입력창에서 새 요청으로 등록합니다.

입금 순서와 이전 이탈은 화면 캐시가 아닌 서버의 해당 참여 업무/입금/이벤트 조회로 확인합니다. 조회 한도에 도달하면 불완전한 횟수를 저장하지 않고 중단합니다. 서버 조회 후 만료일·레코드 버전·업무 버전이 바뀌면 저장하지 않고 재확인을 요청합니다. 동일 밀리초 경합도 기록 버전의 단조 증가로 구분합니다.

미래 결제일·미래 시각, 마지막 입금일보다 오래된 결제, 잘못된 날짜, 이미 처리된 같은 회차는 확인을 요구합니다. 이전 이탈이 있으면 원본을 지우지 않고 자동 갱신에 명시적으로 대체 연결을 저장합니다. 자동 갱신 감사용으로 금액 기록을 추가 생성하지 않으므로 입금 합계가 중복되지 않습니다.

기존 입금을 배포 시 일괄 재처리하거나 과거 만료일을 자동 보정하지 않습니다. 기존 과거 입금과 만료 회차의 연결이 불분명한 건은 별도 확인이 필요합니다.
