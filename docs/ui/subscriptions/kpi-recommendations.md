# 추가 KPI 제안 — 아직 화면에 추가하지 않음

2026-09-07 · 현재 갱신율과 입금 차수 표를 보완하는 제안

| 우선순위 | 추천 표               | 계산 기준                                                                                                             | 용도                                                     |
| -------- | --------------------- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1        | 월별·차수별 실제 수납 | 입금월 × 1차/2차/3차 이상별 실제 입금액 합계와 건수                                                                   | 어느 달에 신규 갱신과 반복 갱신으로 얼마를 받았는지 확인 |
| 2        | 갱신 입금시점 분포    | 입금 완료·기존 만료일 확인 건 중 만료 전 / 만료 후 2개월 이내 / 2개월 초과 건수와 각 비중                             | 안내·연락 시기를 개선                                    |
| 3        | 선납기간 구성         | 구매기간 확인 입금 중 1년·2년·3년 이상 건수. 다년 선납 비중 = 2년 이상 구매 입금 건수 ÷ 구매기간 확인 입금 건수 × 100 | 현금 수납과 다음 만료 시점 차이를 이해                   |

두 번째 표의 분모는 **이미 입금하고 이전 만료일도 확인되는 건**입니다. 미입금 농가가 빠지므로 전체 농가의 ‘정시 갱신율’이라고 부르면 안 됩니다. 2개월은 달력 기준이며 60일이 아닙니다.

세 번째 표는 해당 입금의 구매 연수로 계산합니다. 현행 정상 거래는 66,000원당 1년이지만, 과거 가격 예외·합산 입금은 임의 환산하지 않습니다. 2년 선납 한 건을 갱신 두 번으로 계산하지 않습니다. 분모가 0이면 비율은 ‘—’입니다.

## 참고한 공식 제품 문서

[ChartMogul 수납 지표](https://help.chartmogul.com/article/198-chart-net-cash-flow)는 최초 구독 입금과 후속 입금을 구분합니다. 이 분류를 앱의 1차·2차 이상 입금에 맞춰 적용하는 제안입니다. 단, 앱에는 환불·세금 공제가 완전히 연결되어 있지 않으므로 ‘순수납액’이 아니라 ‘입금액’으로 명명해야 합니다.

[ChartMogul의 수납과 반복매출 구분](https://help.chartmogul.com/article/294-why-does-data-in-chartmogul-differ-from-my-integration)을 참고하여 실제 입금액을 MRR/ARR 또는 회계상 매출로 부르지 않습니다. 위 두 번째·세 번째 산식은 이 앱의 만료·요금 정책에 맞춘 제안이며 외부 제품의 지표를 그대로 복제한 것이 아닙니다.
