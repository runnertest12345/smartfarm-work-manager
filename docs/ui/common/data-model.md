# 데이터 연결과 집계 단위

기준: 2026-09-07 · 소스 커밋 `141faaa`

## 핵심 관계

```text
프로젝트 ─┬─ 제출서류
          ├─ 프로젝트 기록·막힘
          └─ 농가의 사업 참여 정보 ── 농가 기본 정보
                        ├─ 구독 처리 이력
                        └─ 하위 업무
                              ├─ 받은 내용·처리 이력
                              ├─ 체크리스트
                              ├─ 막힘 이력
                              └─ 현장 방문
수신함 ── 업무로 정리 ── 사업 참여 정보에 연결된 하위 업무
```

농가 기본 정보는 한 번 관리하고, 사업별 장비·설치·구독 정보는 참여 정보로 분리한다. 같은 농가가 두 사업에 참여하면 농가는 1개, 사업 참여는 2개이다.

## 데이터 사전

아래 데이터는 선택된 Firestore 작업공간 `workspaces/{workspaceId}` 아래에서 관리된다.

| 화면에서 부르는 이름 | 코드 자료형 / 컬렉션                           | 주요 연결 및 보관 내용                                            |
| -------------------- | ---------------------------------------------- | ----------------------------------------------------------------- |
| 프로젝트·사업        | `FarmProject` / `projects`                     | 연도, 타입, 기관, 목표 농가, 단계, 상태, 정산 금액·상태           |
| 제출서류             | `FarmProjectDocument` / `projectDocuments`     | 프로젝트 ID, 필수 여부, 제출·승인일, 담당자, 보완 상태, 문서 링크 |
| 프로젝트 기록        | `FarmProjectUpdate` / `projectUpdates`         | 프로젝트 ID, 수신·결정·막힘·시스템 기록, 처리 및 해결 내용        |
| 농가 기본 정보       | `Farm` / `farms`                               | 농장번호, 이름, 연락처, 지역·주소, 폴더·위치 링크                 |
| 농가의 사업 참여     | `FarmRecord` / `farmRecords`                   | 농가 ID와 프로젝트 ID, 작목·장비, 설치·시운전·교육, 구독 만료일   |
| 구독 처리 이력       | `FarmSubscriptionEvent` / `subscriptionEvents` | 참여 ID, 기준 만료일, 갱신·이탈·재가입, 처리일, 새 만료일         |
| 수신함               | `FarmInboxItem` / `inboxItems`                 | 경로, 전달자, 받은 내용, 상태, 전환된 업무 ID                     |
| 하위 업무            | `FarmWorkItem` / `workItems`                   | 참여 ID, 유형, 상태, 담당자, 기한, 다음 행동, 응답 목표           |
| 업무 막힘 이력       | `FarmBlockerEpisode` / `blockerEpisodes`       | 업무 ID, 원인, 대기 대상, 열린 시각, 해결 내용·시각               |
| 현장 방문            | `FarmWorkVisit` / `visits`                     | 업무 ID, 예정·실제 방문 시각, 담당자, 준비·결과, 상태             |
| 체크리스트           | `FarmWorkChecklistItem` / `checklistItems`     | 업무 ID, 항목, 완료 여부·담당자·시각                              |
| 진행 히스토리        | `FarmHistoryEntry` / `historyEntries`          | 업무 ID, 받은 내용, 처리 내용, 금액, 기록자, 발생 시각            |

현재 Firestore 구현은 업무 생성 시 참여 정보의 `farmId`를 업무 객체에 복사해 저장한다. 프로젝트 연결은 `farmRecordId`로 참여 정보를 거쳐 찾는다. 승인 목록 `appMembers/{uid}`는 위 작업공간 데이터와 별도로 관리한다.

화면의 ‘전체’ 집계는 실시간 구독으로 읽은 작업공간 데이터를 기준으로 한다. 현재 각 컬렉션의 조회에는 `limit(5000)`이 적용되며 다음 페이지를 합치는 처리는 없다. 한 컬렉션이 5,000건을 넘으면 해당 컬렉션 전체를 반영한 집계라고 볼 수 없다.

## 숫자를 읽는 기준

| 위치                       | 기본 집계 단위                  | 중복 처리                                                                                                |
| -------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 농가 관리대장 상단         | 농가 ID                         | 농가 한 곳을 한 번 집계                                                                                  |
| 농가 관리대장 작목별       | 작목별 농가 ID                  | 같은 작목 안에서는 중복 제거. 여러 작목 농가는 각 작목에 포함                                            |
| 프로젝트 참여·진행률       | 프로젝트 안의 농가              | 같은 농가 참여가 중복되면 최근 활동 참여 레코드 하나 사용                                                |
| 사업 집계의 단계 비율·분포 | 각 프로젝트의 농가 참여 수 합계 | 서로 다른 프로젝트에 참여한 같은 농가는 여러 번 집계. 상단 ‘참여 농가’ 주값은 별도로 고유 농가 수를 표시 |
| 구독 관리 목록             | 참여 레코드                     | 하나의 농가가 여러 줄에 나올 수 있음                                                                     |
| 구독 실적 만료·갱신·이탈   | 참여 ID + 기준 만료일 회차      | 같은 참여·같은 만료 회차를 중복 제거                                                                     |
| 구독 실적 재가입           | 재가입 이벤트 ID                | 처리일 기준 이벤트 수                                                                                    |
| 하위 업무 완료율           | 업무 ID                         | 체크리스트 항목 수나 농가 수가 아님                                                                      |
| 데이터 점검                | 발견된 문제 항목                | 한 농가에서 여러 문제가 발생할 수 있음                                                                   |

## 이력과 현재 상태

현재 상태는 프로젝트·참여·업무 객체에 있고, 변경 경위는 이력에 별도로 남는다. 구독 만료일 수정과 갱신 등록은 목적이 다르다. 만료일 보정은 날짜를 바로잡는 작업이며, 구독 실적을 추가하려면 갱신·이탈·재가입 처리가 필요하다.

화면의 ‘마지막 받은 내용’과 ‘마지막 처리 내용’은 각각 해당 내용이 비어 있지 않은 가장 최근 기록을 찾는다. 두 칸이 서로 다른 시점의 기록일 수 있다.

서류·사진·참고 자료는 URL을 보관한다. 관리 화면에서 파일 자체를 업로드해 보관하는 구조는 아니다.
