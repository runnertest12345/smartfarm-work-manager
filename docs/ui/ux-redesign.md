# 업무 흐름 중심 UX/UI 개편

작성일: 2026-09-07

## 설계 목적

업무를 찾기 위해 긴 카드를 훑거나 다른 화면에서 같은 사업을 다시 찾는 부담을 줄인다. 핵심 경로는 **연도·사업 타입 선택 → 현황 확인 → 해당 프로젝트/업무 목록 → 농가·업무 상세 → 처리 → 이전 위치로 복귀**다. 데이터·권한·저장 방식과 구독 실적 산식은 이번 개편에서 교체하지 않는다.

## 참고한 서적·논문과 적용

아래는 원저자·공식 공개 자료에서 확인한 원칙을 이 관리대장에 적용한 설계 판단이다. 특정 카드 수, 색상 또는 업무시간 감소를 연구가 보장한다는 뜻은 아니다. Norman의 책 전체가 아니라 저자 공개 해설과 소개 자료를 참고했다.

| 근거 | 적용한 원칙 | 이번 화면 변경 |
| --- | --- | --- |
| Don Norman, *The Design of Everyday Things*와 [저자 해설 Design as Communication](https://jnd.org/design-as-communication/) | 사용자가 시스템의 관계와 다음 행동을 이해할 수 있는 일관된 개념모형 | 프로젝트 → 참여 농가 → 업무의 사업 맥락 유지, 상세 경로와 현재 사업 표시 |
| Ben Shneiderman, [The Eyes Have It: A Task by Data Type Taxonomy for Information Visualizations](https://www.cs.umd.edu/~ben/papers/Shneiderman1996eyes.pdf), 1996 | 전체 현황을 보고 필터로 범위를 좁힌 뒤 필요한 상세를 조회 | 핵심 지표 4개 우선 표시, 지표에서 대상 목록으로 이동, 프로젝트 표/카드 보기와 상세 탭 |

| W3C, [WCAG 2.2 Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 충분한 조작 영역과 간격 | 공통 업무 버튼·입력의 최소 높이를 40px로 조정. 기준의 원칙적 최소는 24px 또는 간격·예외 조건이며 40px는 이 제품의 설계 선택 |

## 화면 구성

### 공통

- 메뉴를 ‘현황과 실행 / 농가와 운영 / 집계와 점검’으로 묶는다.
- 상단의 반복적인 기술·보안 안내 배너를 제거한다. 권한·보안 규칙은 유지한다.
- 현재 위치, 사업·농가 건수와 새로고침 상태를 상단에 표시한다.
- 중립 배경과 흰 작업 영역, 진한 본문, 녹색 실행 동작으로 계층을 구분한다.
- 키보드 포커스, 본문 바로가기, 현재 메뉴/상태의 접근성 속성을 제공한다.
- 긴 입력창의 저장·취소 영역을 하단에 고정한다. 닫기 이름은 한국어다.

### 통합 현황·프로젝트 관리

- 상단에는 전체 프로젝트 / 하위 업무 / 업무 완료율 / 처리 필요 업무를 먼저 표시한다.
- 나머지 8개 지표는 ‘설치·구독·서류·정산 지표’에서 펼친다. 계산은 동일하다.
- 연도는 작은 선택 버튼으로, 사업 타입은 명시적인 선택란으로 제공한다. 프로젝트 목록의 중복 연도 선택란은 제거한다.
- 프로젝트 관리 기본 보기는 비교용 표이며 기존 카드 보기도 선택할 수 있다.
- 통합 현황의 프로젝트 이름은 상세로 이동하고, 행 펼침은 하위 업무 미리보기다. 작은 화면에도 펼침 표시를 제공한다.
- 업무 KPI는 같은 연도·사업 타입의 업무 목록으로 연결된다. 처리 필요는 완료 업무를 제외한다.
- 확인 필요의 지연 업무, 구독 만료·미등록, 데이터 점검은 선택한 대상만 보여 주며 범위 해제 동작을 제공한다. 선택된 구독·점검 대상은 진입 시의 ID 집합이며 새로운 대상은 통합 현황에서 다시 진입하면 반영된다.

### 프로젝트 상세

‘진행 요약 / 농가·구독 / 하위 업무 / 제출서류 / 정산 / 처리 이력’으로 나눈다. 설치·운영 세부 지표는 요약 탭에서 펼친다. 하위 업무 표는 상태·담당자·기한·다음 행동을 보여 주고 업무 상세로 연결한다.

농가·구독 탭에서 해당 사업의 구독·입금 화면으로 바로 이동한다. 완료 사업의 서류도 내용과 참고 링크는 열람할 수 있다. 수정·추가는 기존 제한을 유지한다.

### 농가·업무 상세

- 농가 상세는 ‘업무 / 사업·설치·구독 / 처리 이력’으로 나눈다.
- 프로젝트에서 진입하면 해당 사업만 기본 표시하고 ‘전체 참여 사업’ 또는 다른 사업으로 전환할 수 있다.
- 이 범위는 표시할 참여 기록, 업무, 이력 및 새 업무 기본 대상에 함께 적용한다.
- 중복 참여 검사는 화면에 보이는 일부 기록이 아니라 **전체 참여 기록**으로 수행한다.
- 참여 사업 변경 저장 후에는 방금 저장한 사업으로 이동한다.
- 뒤로가기는 이전 상세의 탭과 스크롤 위치를 복원한다. 이전 클릭 대상이 아직 표시되어 있으면 키보드 포커스도 복원한다.
- URL·브라우저 뒤로가기 연동은 이번 변경 범위가 아니다. 앱 안의 이전 상세 버튼을 사용한다.

### 구독·입금·농가 관리대장

- 현재 구독 회차는 접어서 확인하는 보조 현황으로 둔다. 최초·반복 갱신율로 바꾼 것은 아니다.
- 구독 목록은 기존 20건 단위 페이지를 유지하고 내부 640px 세로 스크롤을 제거한다. 가로로 넓은 표의 가로 스크롤은 유지한다.
- 작목별·지역별 농가 분포는 펼침 영역으로 옮겨 농가 검색과 목록에 빨리 도달하게 한다. 각 분포의 농가 필터 동작은 유지한다.

## 검증과 수용 기준

자동 검사: 기존 KPI 계산 9개 및 새 이동 범위·중복 참여 검사 7개. 타입 검사, 접근성 관련 정적 검사, 배포용 빌드는 별도로 실행한다. 단위·정적 검사는 실제 브라우저 사용성 시험을 대체하지 않는다.

운영 반영 전 실제 사용자 확인 항목:

1. 2026년·일반사업 선택 → 처리 필요 업무 → 같은 범위의 미완료 업무만 표시되는지 확인.
2. 프로젝트의 농가 선택 → 해당 사업 확인 → 업무 등록 기본 대상 → 이전 상세 탭/목록 위치 확인.
3. 농가의 다른 사업으로 전환한 뒤 설치·구독·업무가 함께 전환되는지 확인.
4. 완료 사업의 제출서류는 조회가 가능하고 수정은 비활성인지 확인.
5. 구독·입금 검색 → 만료일 정정 → 처리 후 목록 복귀 확인.
6. 작은 화면과 200% 확대, 키보드 이동에서 필터·상세 탭·저장 버튼에 도달 가능한지 확인.
