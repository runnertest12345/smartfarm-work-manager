# 프로젝트 하위 업무와 수신 이미지

기준: 2026-09-08

## 하위 업무의 의미

프로젝트를 진행하기 위한 실행 업무이다. 예: `태백 노지 실증단지 → 견적서 제출`, `문의사항 피드백 후 제출`.

- 프로젝트의 하위 업무·완료율에는 프로젝트에 직접 등록한 업무만 집계한다.
- 구독료 입금, 구독 처리, 자동 관리대장 등록 기록은 하위 업무가 아니다. 기존 기록을 삭제하거나 재분류하지 않는다.
- 업무 현황은 프로젝트 업무와 기존 농가 연락·설치·A/S 등 실제 업무를 함께 제공한다. 입금·구독 및 자동 관리대장 로그는 제외한다.
- 통합 현황의 하위 업무 KPI에서 연 목록은 KPI와 동일한 연도·사업 타입의 프로젝트 하위 업무만 보여준다.
- 프로젝트 최근 활동에는 관련 농가 기록도 계속 포함한다. 활동 기록과 하위 업무 건수는 서로 다른 집계이다.

## 등록·처리 흐름

1. 업무 현황의 **빠른 수신**에서 프로젝트를 선택한다. 프로젝트 상세의 **하위 업무 추가**는 해당 프로젝트를 미리 선택한다.
2. 업무명, 받은 내용, 수신 경로·일시와 기록자를 입력한다. 업무명 미입력 시 받은 내용 첫 부분을 사용한다.
3. **수신함에 담기**를 누르면 수신 원문, 프로젝트 하위 업무, 첫 수신 히스토리가 한 번에 저장된다. 원문은 업무로 전환된 수신함에도 남는다.
4. 업무를 열면 전체 상세 화면에서 **처리 기록·상태 변경**으로 담당자·기한·다음 행동·막힘·처리 내용을 이어 관리한다.
5. 프로젝트를 아직 모르면 **미지정**으로 수신함에 보관한다. 이후 **업무로 정리**에서 프로젝트를 선택하면 농가 선택 없이 하위 업무가 된다. 기존 농가 업무 전환도 유지한다.

완료 프로젝트에 신규 업무는 등록하지 않는다. 미완료 프로젝트 업무가 있으면 프로젝트를 완료할 수 없다. 같은 빠른 수신 저장 요청을 재시도해도 업무를 중복 생성하지 않는다.

## 캡처 이미지

- 빠른 수신, 농가 업무 최초 수신, 진행 기록의 **받은 내용**에 `Ctrl+V`로 붙여넣거나 **이미지 파일 첨부**로 선택한다.
- 텍스트 없이 이미지만 받은 내용으로 저장할 수도 있다. 이미지만 등록한 프로젝트 업무의 기본 제목은 `첨부 이미지 확인 및 처리`이다.
- PNG/JPEG/WebP, 등록 한 번에 최대 3장, 원본 장당 10MB 이하. 큰 이미지는 긴 변 최대 2,560px로 줄이고 자동 압축한다.
- 저장 크기는 장당 384KiB 이하이다. 압축 후에도 크면 오류를 표시하며, 필요한 부분을 나눠 캡처해야 한다. 이미지 처리 중에는 저장·닫기를 막는다.
- 원본 대용량 보관 기능이 아니며, 자동 압축으로 세부 내용이 달라질 수 있다. 원본이 필요한 문서는 기존 참고 링크를 함께 남긴다.
- 수신함과 업무의 수신 히스토리에서 **첨부 이미지 N장 보기**를 눌러 열고 내려받는다. 전환 시 같은 이미지 ID를 참조하여 파일을 중복 저장하지 않는다.

## 데이터·권한

`workItems.projectId`로 프로젝트에 직접 연결하고 `farmRecordId`, `farmId`는 빈 문자열이다. 기존 농가 업무의 연결 방식은 그대로 둔다. 이미지 참조는 `inboxItems.imageIds`와 `historyEntries.imageIds`에 저장한다.

파일 내용은 별도 `workspaces/{workspaceId}/imageAttachments/{imageId}` 문서에 보관한다. 전체 작업공간 실시간 목록에 포함하지 않고 사용자가 이미지를 열 때만 읽는다. 이미지 문서 필드 색인은 비활성화한다.

기존 인증·활성 구성원 권한을 그대로 적용하며, 이미지 문서는 생성·개별 조회만 허용한다. 공개 접근, 전체 목록 조회, 덮어쓰기, 삭제는 허용하지 않는다. 부모 수신/기록에 연결된 이미지 ID만 같은 저장 작업으로 생성할 수 있다. 파일과 부모 기록 중 일부만 저장되지 않도록 원자적으로 처리한다.

현재 Firebase 구조를 유지하며 유료 저장소를 새로 활성화하지 않는다. 무료 할당량을 무제한으로 보장하는 설계는 아니다. 이미지 사용이 늘어나면 사용량을 확인하고 전용 파일 저장소로 이전할 필요가 있다.

## 검증

- `scripts/test-subscription-payment.mjs`: 기존 입금·갱신 회귀, 프로젝트 수신 원자성·중복 방지, 이미지 전환·제한, 프로젝트 업무 처리.
- `scripts/test-project-image-rules.mjs`: 기존 CLI 인증으로 Rules 검사 API를 호출한다. 가상 요청과 모의 문서만 사용하며 실제 데이터는 쓰지 않는다. 로그인·활성 권한, 이미지 연결·수정 방지, 프로젝트 업무와 기존 농가 입금 관계를 확인한다.
