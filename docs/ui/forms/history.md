# 진행 기록 추가

기준 커밋: `141faaa` · 작성일: 2026-09-07

DialogKind: `history`

열리는 경로: 업무 상세 ‘진행 기록 추가’. 선택 업무의 현재 상태·담당자·기한·우선순위·완료 기준·다음 행동·검토일·대응 목표·막힘 정보를 채운다. 이력 경로는 전화, 발생 일시는 현재, 받은/처리 내용과 기록자는 빈 값으로 시작한다.

필드: 수신 경로, 변경 상태, 담당자, 처리 기한, 우선순위, 다시 볼 날짜, 최초 대응 목표, 최초 대응 완료 토글(아직 미응답일 때만), 다음 행동, 완료 기준, 발생 일시, 전달자·기관, 받은 내용, 처리 내용/해결 내용, 금액(원·min 0), 기록자, 참고 링크(URL). 대기 상태에는 막힘 사유·해제에 필요한 사람/기관(required)·예상 해제일을 표시한다.

저장 필수는 기록자이며, 대기 유지/진입에는 사유·주체가 필요하다. 기존 대기를 다른 상태로 바꾸면 해결 내용이 required다. 받은/처리 내용이 모두 비어도 계획 갱신을 저장할 수 있다. 완료를 선택하면 다음 행동·검토일 입력이 잠기고 저장값은 비워진다. 최초 대응 기록 이후, 이번 기록의 최초 대응 토글 선택, 완료 선택 시에는 목표 입력을 잠그고 기존 목표를 보존한다.

저장: history POST로 새 이력을 추가하고 업무의 현재 계획·상태를 갱신한다. 수신/처리 내용이 모두 없으면 시스템 경로와 변경항목 요약(변경 없으면 계획 검토)을 이력으로 만든다. 최초 대응 토글 또는 완료는 미응답 업무에 발생시각을 최초 대응시각으로 남긴다. 일반 처리 내용만 입력하는 것은 이 폼에서 최초 대응 토글과 동일하지 않다. 입금 업무의 양수 금액은 마지막 입금일을 더 늦은 날짜로 갱신한다.

대기 진입은 막힘 이력을 생성, 유지 중 편집은 열린 막힘 이력을 수정, 해제는 발생시각·해결 내용을 남긴다. 완료 전환은 미완료 체크리스트나 예정 방문이 있으면 경고와 함께 저장을 거절한다. 완료 사업 업무의 재개도 거절한다. 완료시각은 최초 완료일을 유지하고 재개하면 0으로 바꾼다. 기존 히스토리를 고치는 폼은 아니다.
