# 내부 업무·직원 계정·부서장 지시

갱신일: 2026-09-09.

## 직원 계정과 외부 가입 차단

외부 회원가입 양식과 가입 신청 저장 경로는 제공하지 않는다. Firebase의 `client.permissions.disabledUserSignup`도 활성화하여 공개 가입 요청을 차단한다. 기존에 등록된 Google/이메일/공용 계정의 로그인은 유지한다. 개인 아이디는 한글·영문·숫자·밑줄 2~10자로 사용하며 이메일을 요구하지 않는다. Firebase 내부 식별용 `.invalid` 주소는 실제 메일 주소가 아니며 화면에 노출하거나 메일을 보내지 않는다.

초기 등록 대상은 평화(부서장), 러너(팀장·관리자), 담호(직원)이며 `공통 부서`로 묶는다. 부서장은 departments.headUid로, 팀장/직원은 jobTitle로, 관리자 권한은 admin으로 따로 관리한다. 러너는 `직원·부서 관리`에서 등록된 직원의 부서·직책·접근 상태 및 부서장을 관리한다. admin 필드는 웹 클라이언트에서 변경할 수 없다.

사용자 선택에 따라 이번 범위는 **외부 가입 차단과 초기 세 계정 생성**까지다. 러너·평화 전용 신규 회원 등록 화면/서버는 보류했다. 신규 계정은 신뢰할 수 있는 운영자 경로에서만 추가한다. 아이디 계정은 이메일 비밀번호 찾기 대신 운영자에게 기존 UID의 비밀번호 재설정을 요청한다.

임시 비밀번호는 소스나 문서에 저장하지 않는다. 초기 계정은 첫 로그인 시 새 비밀번호(10자 이상)와 확인 입력 화면을 보여준다. Auth 비밀번호 변경에 성공한 뒤 안내 플래그를 해제하며, 후속 저장이 실패하면 새 암호를 재변경하지 않고 확인 저장만 재시도한다. 이는 **첫 로그인 안내·UI 차단**이며 Firestore 플래그가 실제 Auth 암호 변경을 증명하는 서버 강제 정책은 아니다. 다른 계정과 공유된 임시 암호이므로 실제 사용 전 각자 변경해야 한다.

## 내부 업무

업무 현황 → `업무 등록` → `내부 업무` → 업무명·담당 계정 선택 → 저장. 기한·받은 내용·캡처는 선택이다. 프로젝트 업무를 선택하면 실제 프로젝트에 연결된다.

- 내부 업무는 가짜 프로젝트나 농가를 만들지 않으며 프로젝트 수·설치·구독·입금 KPI에서 제외한다.
- 보드/목록에서 전체·내부·프로젝트/농가를 구분하고, 개인 계정은 내 업무·우리 부서·내 부서장 지시를 선택할 수 있다.
- 같은 부서의 내부 업무 아래 세부 업무와 손자 업무를 추가한다. 자식 완료 후 상위 담당자가 최종 완료 확인한다.
- 빠른 수정은 중앙 팝업이다. 계정 배정된 담당자는 임의의 텍스트 이름으로 변경할 수 없다. 재배정 기능은 현재 제공하지 않는다.
- 등록/변경의 동시 충돌·중복 재전송 검증은 기존 경로를 사용한다.

## 부서장 지시·최우선

등록하는 개인 계정이 **담당 직원과 같은 부서의 지정된 부서장**이면 자동으로 최우선 지시가 된다. 자기 자신이나 다른 부서 직원에게 배정하면 일반 업무다. 입력창 미리보기뿐 아니라 저장 시 최신 직원/부서 자료와 보안 규칙에서 재확인한다.

등록 당시 배정자 UID·담당 UID·부서·시각·부서장 지시 여부를 보호한다. 나중에 부서장이 바뀌어도 과거 일반 업무를 소급 승격하지 않는다. 미완료 지시는 목록과 해당 상태 열에서 먼저 나오며 세부 업무가 최우선이면 상위 카드 묶음이 먼저 나온다. `내 최우선 N건`은 검색·유형·상태 필터를 초기화하여 내 미완료 지시를 보여준다.

완료하면 최우선 대기 건수에서 빠지지만 지시 이력은 유지한다. 다시 열면 최우선으로 돌아온다. 자동으로 처리 중/완료로 바꾸거나 다른 업무 처리를 차단하지 않는다.

기존 공용 접속은 유지하지만 개인 배정·부서장 지시 생성·계정 관리는 할 수 없다. 기존 자유 입력 담당자를 이름만 보고 계정에 자동 연결하지 않는다. 업무 자료는 기존처럼 승인된 작업공간 구성원에게 공유되며 개인별 비공개 기능은 아니다.

## 저장과 검증

`appMembers`에는 가입/승인/부서를, `workspaces/{workspaceId}/departments`에는 부서·부서장을 저장한다. 업무는 기존 workItems·처리 이력·사진 구조를 사용한다. 새 계정은 해당 작업공간으로 접근을 제한하고, 기존 작업공간 필드가 없는 승인 계정의 접근은 보존한다.

가상 계정/업무 자동 테스트와 Firebase Rules API의 가상 문서 평가를 사용한다. 운영자 전용 `scripts/provision-initial-members.mjs`는 대상 충돌을 먼저 확인하고 고정 UID로 최초 생성만 한다. 재실행으로 기존 암호·권한을 덮어쓰지 않는다. 스크립트/CLI 자격증명은 정적 사이트에 배포하지 않는다.

참고: [Firebase 사용자 관리](https://firebase.google.com/docs/auth/web/manage-users), [보안 규칙 조건](https://firebase.google.com/docs/firestore/security/rules-conditions).
