# 업무 계층·빠른 수정·기록 간소화

갱신일: 2026-09-15. 기존 보드·목록·진행 기록 문서와 다르면 이 문서의 최신 동작을 따른다.

업무 현황 제외: 원본 관리대장에서 이관한 파모스박스 교체 완료 이력은 보드·목록·관제·주간 검토의 업무 대상에 포함하지 않는다. 이관 출처, 완료 상태, 원본 시스템 이력과 교체 처리 결과를 함께 확인한다. 제목에 ‘교체’가 있다는 이유만으로 숨기지 않으며, 신규 교체 요청·재개한 업무·추가 처리 기록이 생긴 업무는 유지한다. 농가 상세와 A/S 이력의 원본 데이터는 삭제하거나 변경하지 않는다.

## 업무 연결

업무 목록·상세의 세부 업무 표는 부모 바로 아래에 자식을 이어 붙이는 트리형 목록이다. 형제는 같은 위치에 정렬하고, 한 단계마다 32px 들여쓰기와 연속 연결선으로 관계를 표시한다. 실제 최상위 업무는 연한 녹색 배경과 굵은 제목, 자식은 흰 배경과 `하위 업무` 표식으로 구분한다. 상세 화면에서 첫 행으로 표시되는 자식도 하위 표식을 유지한다. 들여쓰기는 최대 128px(4단계)로 제한하고, 더 깊은 업무는 실제 단계와 상위명을 함께 표시한다. `1 → 1.1 → 1.1.1` 목록 번호는 제목 도움말과 보조기기용 정보로 제공한다. 번호는 현재 목록의 표시 순서이며 영구 업무번호나 저장 필드가 아니다. 접기·검색만으로 번호를 다시 매기지 않는다.

업무 목록은 처음에 상위 업무와 바로 아래 세부 업무까지만 표시한다. 선택한 업무의 상세에서는 그 업무의 직접 자식만 기본 표시한다. 더 깊은 업무는 화살표로 펼치며 데이터나 실제 계층은 변경하지 않는다. `모두 접기`·`모두 펼치기`는 현재 조회한 묶음의 표시만 바꾸고, 이후 실시간으로 도착한 깊은 묶음은 기본 접힘을 유지한다. 검색 중에는 필요한 조상을 펼치며 검색 해제 후 사용자가 선택한 접힘 상태를 복원한다. 조회 갱신만으로 펼침 선택을 초기화하지 않는다. 자식이 있는 업무는 제목 바로 아래에 `최하위 실행 완료 n/N · 완료율 · 처리 중 n · 대기·막힘 n`과 얇은 완료율 막대를 항상 표시한다. 이 요약은 접힌 자손과 검색에서 제외된 형제도 포함한 전체 하위 업무 기준이며, 새로운 수정 버튼을 만들지 않는다. 완료율·처리 중·대기·막힘은 최하위 실행 업무만 집계해 중간 부모와 중복되지 않는다. 중간 부모의 막힘은 `중간 업무 대기·막힘 n건`으로 따로 안내한다. 일부 자식이 조회되지 않으면 완료율과 막대를 숨기고 조회 확인 문구를 표시한다. 최근 수신·처리 기록·다음 행동만 `최근 기록·다음 행동`을 펼쳐 확인한다. 업무명·상태·담당자·기한·작업을 별도 열로 정렬하며, 상태·담당자·기한은 각 업무의 값을 유지한다.

상태·담당자·기한을 클릭하면 해당 업무의 빠른 수정 창을 직접 연다. 담당자·기한은 선택 영역을 미리 펼치고 해당 입력으로 초점을 이동한다. 직원 계정에 연결된 담당자 이름은 기존처럼 읽기 전용이며 임의로 이름만 바꾸지 못한다. 행에는 `빠른 수정`과 `더보기`만 반복 노출하고, 세부 업무 추가·삭제는 키보드로 접근 가능한 더보기 메뉴에 모은다. 삭제는 기존 권한 검사와 확인창을 그대로 사용하며, 완료된 업무·프로젝트·상위 업무의 추가/상태 잠금도 유지한다.

선택한 업무의 상세는 전체 업무 그래프에서 실제 상위 관계와 완료 잠금을 확인하고, 표에는 선택한 업무의 자손만 표시한다. 선택한 상위가 표에 없다는 이유로 연결 오류를 표시하지 않는다. 저장된 부모를 실제로 조회하지 못한 경우에만 연결 확인을 안내한다.

업무 목록과 상세의 행 사이에는 카드식 여백을 두지 않고 얇은 구분선만 사용한다. 제목과 펼침 화살표를 같은 줄에 놓아 부모·자식의 소속과 이름이 먼저 보이게 한다. 기존 열 정렬·펼치기 동작은 유지한다. 프로젝트 밖의 [내부 업무와 계정 배정](internal-tasks.md)도 같은 실행 업무 구조를 사용하되 사업 KPI에는 포함하지 않는다.

프로젝트 → 하위 업무 → 세부 업무 → 추가 세부 업무로 연결한다. 예: 태백 실증단지 → 견적서 제출 → 내부 검토 → 수정 내역 확인. 각 업무는 담당자·기한·상태·수신/처리 이력을 독립적으로 가진다. 구독 입금과 구독 처리 기록은 프로젝트 하위 업무에 포함하지 않는다. 기존 업무를 임의로 계층에 편입하거나 과거 데이터를 삭제하지 않는다.

통합 현황의 프로젝트 펼침 영역은 중첩 카드 대신 **계층형 표**를 사용한다. 업무명·상태·담당자·기한·최근 처리 내용의 5개 열을 고정된 순서로 정렬하고, 하위 업무 하나를 하나의 행 묶음으로 표시한다. 부모→자식→손자 순서와 부모 행의 배경·세부 업무의 들여쓰기·연결선·단계 표시로 소속 관계를 구분한다. 업무명은 잘라내지 않고 줄바꿈하며, 최근 처리 내용은 2줄 요약과 상세 이동으로 확인한다. 최근 처리 이력 → 다음 행동 → 빈 안내 순서를 유지한다. 작은 화면에서는 표를 좌우로 스크롤하고, 깊은 업무의 들여쓰기는 3단계 너비까지만 늘려 내용 공간을 확보한다.

각 부모의 화살표는 세부 업무를 접거나 펼치기만 하며, 업무명 선택은 해당 업무의 상세만 연다. 상태와 기한은 부모 값을 대신 보여주지 않고 각 업무의 원래 값을 표시한다. 목록·프로젝트 업무 탭의 기존 계층형 목록과 빠른 수정·보드 기능은 유지한다. 변경은 표시 방식에 한정하며 업무·이력 데이터나 KPI 산식은 수정하지 않는다.

프로젝트별로 처음 8개 하위 업무 묶음을 표시하며 세부 업무를 중간에 잘라 다른 묶음으로 만들지 않는다. 더 보기는 남은 묶음 수를 표시한다. 묶음은 그 안의 가장 긴급한 업무 순서를 따르고, 형제 업무도 긴급도 순서를 유지한다. 검색에 세부 업무만 일치해도 조상 경로를 함께 표시하고 펼친다. 검색/접힘은 전체 실행 업무 집계와 완료율에 영향을 주지 않는다. 프로젝트 상단의 ‘실행 업무’는 접수·처리 중·대기·완료와 동일한 최하위 업무 기준이며, 하위 업무 수와 세부 업무 수는 목록 제목에 별도로 표시한다. 조회되지 않은 세부 업무가 있으면 조회 확인 안내를 표시한다.

목록·프로젝트 업무 탭에서 화살표로 세부 업무를 접거나 펼친다. 업무 상세 헤더에서는 `처리 기록·상태 변경` 옆의 `+ 세부 업무 등록`을 바로 눌러 다음 단계를 만든다. 상세의 더보기에는 등록을 중복 표시하지 않고 삭제만 둔다. 목록 행에서는 기존 `더보기 → 세부 업무 추가`를 유지한다. 업무명은 필수이며 담당자는 상위 업무에서 가져오고, 기한·받은 내용·캡처는 선택 입력이다. 완료 업무·완료 프로젝트의 등록 제한과 기존 권한 검사는 유지한다. 상세에서는 상위 업무로 이동할 수 있다.

## 상세 업무명 바로 수정

프로젝트·내부·농가 업무 상세에서 제목과 연필 아이콘을 누르면 같은 위치에서 업무명을 수정한다. 저장·취소만 표시하며 별도의 팝업을 겹치지 않는다. 승인된 개인 계정이 일반 업무명을 1~200자로 수정할 수 있고, 입금·구독 증빙과 삭제 업무는 제외한다. 완료된 업무도 이름을 정정할 수 있다.

제목 저장은 제목·수정 시각·수정자와 이름 변경 이력만 기록한다. 상태·완료 정보·하위 연결·담당자·막힘 사유·금액·기존 처리 기록을 변경하지 않는다. 저장 실패·외부 수정 시 초안을 유지하며 오래된 버전으로 덮어쓰지 않는다. 제목 초안이나 저장이 진행 중이면 상세 이동·뒤로가기·기록 추가·삭제를 먼저 막는다. 외부에서 삭제돼도 수정 중 초안은 유지하고 취소할 수 있다. 같은 내용의 저장 재시도는 한 번만 반영한다.

## 보드와 빠른 수정

2026-09-15 [보드 동작](board.md): 최상위 업무당 카드 한 장으로 묶고 담당자·기한·하위 완료율·막힘 건수를 간결하게 요약한다. 카드 아래 하위 업무명·상태를 부모→자식 순서와 단계별 16px 들여쓰기로 구분한다. 형제는 같은 위치이며 들여쓰기는 최대 64px로 제한한다. 실제 단계와 바로 위 상위명을 유지하고, 대기·막힘의 사유·확인 대상은 노란색으로 강조한다. `하위 업무 N개` 헤더로 목록만 접고 펼치며, 접어도 막힘 건수와 업무명 요약은 남긴다. 보드를 열 때와 새 카드가 도착할 때는 기본 접힘이며, 직접 펼친 카드별 선택은 같은 보드의 실시간 갱신·검색·열 이동에도 유지한다. 새로고침하거나 보드를 다시 열면 모두 접힌다. 하위 목록만 높이를 제한해 스크롤한다. 상위·하위 업무명은 해당 전체 상세 팝업을 연다. 긴 기록과 전체 계층은 팝업에서 조회한다. 각 열 숫자는 표시 카드 수다. 카드 위치는 상위 업무의 저장 상태를 따르되, 하위·손자·중간 부모 중 하나라도 대기·막힘이면 대기 열에 우선 표시한다. 하위 대기 건수와 상위의 실제 상태를 구분해 보여준다. 저장된 부모 상태·대기 사유·이력을 자동 변경하지 않으며, 하위 대기가 해제되면 상위가 마지막으로 직접 선택한 열로 돌아간다.

상위 카드의 손잡이로 상태 열에 드롭하면 해당 상위 업무만 변경한다. 하위 업무는 전체 팝업의 상태 선택·빠른 수정으로 변경한다. 상위 이동으로 하위 상태를 일괄 변경하거나 세부 업무 선택창을 열지 않는다. 상위의 접수·처리 중 이동은 하위 상태와 독립적이지만, 미완료 하위 업무가 있으면 상위 완료를 막는다. 전체 자손이 완료됐을 때 담당자가 상위 업무를 최종 확인하며 중간 부모의 확인도 생략하지 않는다. 세부 업무명으로 상세를 열거나 상태 선택·빠른 수정으로 해당 한 업무를 수정한다. 각 행의 더보기 메뉴에서 다음 단계 업무를 등록한다. 완료 열에 임의의 5건·최근 7일 제한은 없다.

드래그가 어려운 모바일·키보드에서는 ‘빠른 수정’을 사용한다. 빠른 편집기는 현재 목록/보드 위의 중앙 팝업으로 열리며 배경 스크롤 위치는 유지한다. 내용이 길면 팝업 안에서 스크롤한다. 열이 외부 수정으로 바뀌어도 초안을 유지한다. 키보드·마우스로 열면 상태(상태 변경이 잠겼으면 처리 내용)에 초점을 주고, 닫으면 시작 버튼으로 돌린다. 바깥 클릭으로 닫히지 않으며 변경 후 취소·닫기·Esc는 초안 취소를 확인한다. 저장·이미지 처리 중 닫기와 열린 입력창을 둔 뒤로가기를 막는다. 저장 성공 시 닫히고, 저장 실패 시 작성 내용을 남긴다. 완료 부모 아래의 자식은 상태 재개를 제한하되 완료 상태를 유지한 처리 내용·캡처 추가는 허용한다. 받은 내용과 처리 내용은 각각 최신의 비어 있지 않은 이력을 요약한다.

## 적게 입력하는 기록

일반 진행 기록의 기본 항목은 **상태와 처리 내용**이다. 상태만 바꾸어도 시스템 변경 이력이 생기므로 처리 내용을 중복해서 적을 필요가 없다. 변경값이 전혀 없으면 저장하지 않는다.

- 작성자: 로그인한 계정 표시 이름/이메일로 자동 입력.
- 작성 시각: 입력창을 연 시각을 자동 기록.
- 받은 내용·캡처, 수신 경로: 선택 영역을 펼쳐 입력. 이미지는 기존 비공개 저장 정책을 따른다.
- 담당자·기한·다음 행동: 바꿀 때만 선택 영역을 펼친다.
- 금액·기록자·발생 시각을 매번 입력하던 항목은 일반 빠른 기록에서 제거했다. 입금 전용 폼과 기존 데이터는 유지한다.
- 우선순위·완료 기준·대응 목표 등은 ‘상세 계획’에서만 조정한다. 미저장 초안이 있으면 이 전환을 막는다.
- 대기·막힘일 때만 사유와 확인할 사람/기관이 필수이다. 대기를 해제할 때만 해결 내용을 필수로 받는다.

프로젝트 직접 기록도 기본은 기록 구분·제목·처리 내용이다. 작성자는 로그인 계정, 일시는 현재로 채우며, 수신 경로·발신자·받은 내용·참고 링크·과거 일시 수정은 선택 영역에 둔다.

## 완료율과 안전장치

상위 업무와 세부 업무 수를 따로 표시한다. 실행 업무는 더 작은 세부 업무가 없는 최하위 업무이다. 완료율 = 완료 실행 업무 ÷ 전체 실행 업무 × 100. 상위 묶음을 분모에 중복해서 더하지 않는다. 자식 ID가 있지만 일부 문서를 조회하지 못하면 완료율을 산출하지 않는다.

자식 상태를 모두 완료해도 상위 상태가 자동 완료되지는 않는다. 상위 담당자가 최종 확인하여 완료한다. 미완료 자식, 미완료 체크리스트, 예정된 방문이 있으면 완료할 수 없다. 완료된 상위 업무 아래에서 다시 작업하려면 상위를 먼저 다시 연다.

부모·자식 링크와 미완료 자식 수는 같은 트랜잭션에서 저장하고 보안 규칙으로 교차 검증한다. 다른 사용자가 먼저 변경했으면 오래된 초안으로 덮어쓰지 않으며 작성 내용과 안내를 유지한다. 생성/수정 요청 ID로 응답 실패 후 재전송의 중복 업무·이력을 방지한다. 부모 관계는 등록 후 임의로 바꾸지 못하며, 순환·다른 사업 연결을 거절한다. 한 업무의 직접 세부 업무는 최대 500개이다.

2026-09-11: 내부·프로젝트 업무의 중첩된 부모에 세부 업무를 추가할 때 보안 규칙의 표현식 평가 한도를 넘는 문제를 수정했다. 회원·감사 필드·상태·자식 개수의 반복 계산을 재사용하고, 내부 업무는 바로 앞 배정 검사에서 확인한 동일 연결 조건만 재검사하지 않는다. 계정 권한·관계 검증·개수 제한은 변경하지 않는다. 내부 연결 검증을 바꿀 때는 `validWorkAssignment`와 `workUpdate`의 중복 생략 조건을 함께 검토한다.

코드: `app/project-work-tree.tsx`, `app/work-task-controls.tsx`, `lib/work-hierarchy.ts`, `lib/firebase/farm-ledger-store.ts`, `firestore.rules`.

검증: 가상 데이터의 계층·이력·중복·오래된 버전·입금 회귀 테스트, 컴포넌트 입력/이벤트 테스트, 가상 문서 기반 보안 규칙 평가. 실제 운영 데이터에 테스트 업무를 생성하지 않는다.
